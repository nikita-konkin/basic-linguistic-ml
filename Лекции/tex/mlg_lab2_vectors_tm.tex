\begin{frame}{Цель работы}
\color{ink}
{\small Сравнить меры сходства при поиске по памяти переводов. Объяснить расхождения на конкретных запросах и выбрать способ проверки подсказок.}
\врезка{Одинаковый процент или косинус у разных методов не означает одинаковую полезность для переводчика.}
\end{frame}

\begin{frame}{Память переводов}
\color{ink}
{\small Память переводов (translation memory, TM) — база пар «исходный сегмент — перевод». При поступлении нового сегмента система ищет похожие исходные сегменты и предлагает связанные переводы.
\par\vspace{0.6em}В учебной работе поиск выполняется по русской стороне корпуса. Это удобно для разбора морфологии и перефразирования; направление отличается от обычного поиска нового оригинала в TM.}
\end{frame}

\begin{frame}{Точное и нечёткое совпадение}
\color{ink}
{\small При точном поиске строки должны совпасть по заданным правилам нормализации. Нечёткий поиск ранжирует кандидатов по мере сходства.
\par\vspace{0.6em}Алгоритм возвращает ближайший сегмент даже тогда, когда подходящего перевода в памяти нет.}
\врезка{Нужно проверять не только порядок кандидатов, но и достаточность сходства. Ближайший ответ может оказаться непригодным.}
\end{frame}

\begin{frame}{Расстояние Левенштейна}
\color{ink}
{\small Расстояние Левенштейна — минимальное число вставок, удалений и замен символа, необходимых для преобразования одной строки в другую.
\par\vspace{0.6em}«кот» и «кит»: одна замена. «кот» и «скот»: одна вставка. Для «кот» и «скоты» нужны две вставки.}
\врезка{В этом определении перестановка двух символов не является отдельной операцией. Для неё существуют другие варианты редакционного расстояния.}
\end{frame}

\begin{frame}{Как вычисляют редакционное расстояние}
\color{ink}
{\small \[\displaystyle D_{i,j}=\min\begin{cases}D_{i-1,j}+1\\D_{i,j-1}+1\\D_{i-1,j-1}+[a_i\ne b_j]\end{cases}\]
\par\vspace{0.6em}$D_{i,j}$ — расстояние между первыми $i$ и $j$ символами строк. Три случая соответствуют удалению, вставке и замене; совпавшие символы не требуют правки.}
\врезка{Начальные значения: $D_{i,0}=i$, $D_{0,j}=j$. Таблица строится от коротких префиксов к полным строкам.}
\end{frame}

\begin{frame}{Нормированный процент сходства}
\color{ink}
{\small \[\displaystyle s(a,b)=100\left(1-\frac{D(a,b)}{\max(|a|,|b|)}\right)\]
\par\vspace{0.6em}$|a|$ и $|b|$ — длины строк. Для совпадающих строк результат равен 100 \%. Случай двух пустых строк обрабатывают отдельно.}
\врезка{Это формула учебной работы. Конкретные CAT-системы могут иначе учитывать теги, числа, порядок слов и штрафы.}
\end{frame}



\begin{frame}{Косинусное сходство}
\color{ink}
{\small \[\displaystyle \cos(\mathbf a,\mathbf b)=\frac{\sum_j a_jb_j}{\sqrt{\sum_j a_j^2}\sqrt{\sum_j b_j^2}}\]
\par\vspace{0.6em}Косинус сравнивает направления ненулевых векторов. Для неотрицательных TF-IDF-векторов лежит от 0 до 1; для произвольных векторов возможны отрицательные значения.}
\врезка{Умножение всего вектора на положительное число косинус не меняет. Добавление новых слов меняет направление и может изменить сходство.}
\end{frame}

\begin{frame}{Эмбеддинги: что означает близость}
\color{ink}
{\small Эмбеддинг — плотный числовой вектор, полученный обученной моделью. Сходство таких векторов может отражать близость тематики и употребления.
\par\vspace{0.6em}Синонимичные строки могут оказаться близкими даже без общих слов. Строки с противоположным смыслом тоже могут быть близки, если отличаются одним отрицанием.}
\врезка{Векторы в папке data уже вычислены. Для новых текстов требуется запуск совместимой модели эмбеддингов.}
\end{frame}

\begin{frame}{Один запрос, несколько оценок}
\color{ink}
{\small Запрос: «Сохранить все изменения». Близкий сегмент: «Сохранить изменения».
\par\vspace{0.6em}В опыте курса: сходство по Левенштейну — 82,6 \%, косинус по символьным n-граммам — 0,909, по готовым эмбеддингам — 0,958.}
\врезка{Значения относятся к разным шкалам. Они не являются вероятностью правильности подсказки.}
\end{frame}

\par\vspace{0.6em}Левенштейн и символьные n-граммы возвращают один и тот же ближайший сегмент для 9 запросов. Оставшиеся 4 особенно полезны для сравнения методов.}
\end{frame}

\begin{frame}{Перестановка и изменение словоформ}
\color{ink}
\begin{columns}[T,onlytextwidth]\column{0.47\textwidth}{\small Запрос: \textbf{«Настройки поиска»}.
\par\vspace{0.6em}Левенштейн: «Начните за три простых шага.», 28,6 \%.
\par\vspace{0.6em}N-граммы: «Поиск по настройкам», косинус 0,696.}
\column{0.47\textwidth}{\small Левенштейн учитывает порядок символов. Общие n-граммы сохраняются и при изменении порядка слов и окончаний.}\end{columns}
\врезка{Запрос одновременно меняет порядок и грамматическую форму. Чтобы изучить только один фактор, нужен отдельный минимальный пример.}
\end{frame}

\begin{frame}{Номинализация и коммуникативная функция}
\color{ink}
\begin{columns}[T,onlytextwidth]\column{0.47\textwidth}{\small Запрос: «Сохранение изменений». Левенштейн находит «Сохранить изменения» (75,0 \%), n-граммы — «Изменения сохранены» (0,760).}
\column{0.47\textwidth}{\small Фразы относятся к одному действию, но выполняют разные функции: название процесса, команда и сообщение о результате.}\end{columns}
\врезка{Лексическое сходство не делает строки взаимозаменяемыми. Подходящая подсказка зависит от того, где строка используется.}
\end{frame}

\begin{frame}{Короткая подсказка для длинного запроса}
\color{ink}
{\small Запрос: «Пожалуйста, очистите кэш и повторите попытку». N-граммы находят «Очистить кэш» с косинусом 0,591.
\par\vspace{0.6em}Короткий кандидат покрывает только часть инструкции. Нормированное редакционное расстояние дополнительно учитывает несовпадение длины.}
\врезка{Частичную подсказку можно использовать при редактировании. Автоматически заменять ею весь запрос нельзя.}
\end{frame}

\begin{frame}{Перефразирование без общих слов}
\color{ink}
{\small Запрос: «По вашему запросу результатов нет». Ожидаемая подсказка: «Ничего не найдено».
\par\vspace{0.6em}Левенштейн, n-граммы и LSA не помещают её в первую тройку. Готовые эмбеддинги находят её на втором месте.}
\врезка{Результат оценивают по нескольким позициям списка. Один неудачный первый ответ ещё не описывает весь поиск.}
\end{frame}

\begin{frame}{Оценка поиска: Hit@k}
\color{ink}
{\small \[\displaystyle \mathrm{Hit@}k=\frac{\text{запросы с нужным ответом в первых }k}{\text{запросы с известным нужным ответом}}\]
\par\vspace{0.6em}Для каждого запроса заранее определяют пригодные подсказки. Затем проверяют, попала ли хотя бы одна из них в первые k результатов.}
\врезка{Если подходящего сегмента в памяти нет, такой запрос нужен для отдельной проверки отказа от подсказки.}
\end{frame}

\begin{frame}{Точность отбора и полнота}
\color{ink}
{\small Точность отбора (precision) — доля пригодных подсказок среди показанных. Полнота (recall) — доля найденных пригодных подсказок среди всех доступных.
\par\vspace{0.6em}При пороге 75 \% точность показанных подсказок равна 6/7. Для полноты нужен заранее размеченный набор запросов, где подсказка действительно существует.}
\врезка{Порог выбирают по цене пропуска и лишней проверки. На маленьком наборе он служит демонстрацией компромисса.}
\end{frame}

\begin{frame}{Кластеризация сегментов}
\color{ink}
{\small Кластеризацию используют для обзора корпуса без готовых меток. В работе k-средних сравнивается на TF-IDF, LSA и готовых эмбеддингах.
\par\vspace{0.6em}ARI позволяет проверить, насколько найденные группы совпали с типами контента. Низкое совпадение не объясняет его причины автоматически.}
\end{frame}

\begin{frame}{Терминологические кандидаты}
\color{ink}
{\small Слова с высоким средним TF-IDF внутри типа контента можно рассмотреть как кандидатов в характерную лексику. Сравнение с другими типами помогает выделить отличия.
\par\vspace{0.6em}Редкость слова и связь с категорией ещё не делают его термином. Нужно проверить обозначаемое понятие, употребление и варианты перевода.}
