# Основы машинного обучения — магистратура лингвистики

Комплект материалов дисциплины для направления **«Цифровая лингвистика
и локализация»**.

Для студентов материалы выложены на сайте курса:
**https://konkin-nikita.ru/basic-linguistic-ml/** — лекции, лабораторные,
расписание и журнал группы (см. [«Сайт курса»](#сайт-курса)).

## Сквозной кейс

Три лабораторные работы — не отдельные упражнения, а этапы одной задачи:
**конвейер локализации англо-русского программного продукта**. Каждая
работа берёт результат предыдущей и добавляет к нему шаг.

| | работа | этап конвейера | что студент умеет после |
|---|---|---|---|
| 1 | Классификация текстов | разбор входящего материала по типу контента | превратить текст в признаки и объяснить, почему один способ лучше другого |
| 2 | Векторные представления и память переводов | нечёткий поиск по TM, извлечение терминологии | выбрать меру сходства под задачу и обосновать выбор |
| 3 | Машинный перевод и оценка качества | приёмка перевода | измерить качество, найти слепые зоны метрик и закрыть их |
| 4 | Генерация текста | демонстрация на одно занятие | понимать, как устроена языковая модель |

Все работы конвейера используют **один корпус** — `Л.р/data/loc_corpus.csv`.

Пятая работа — вводная `Л_р_№1_Классификация.ipynb`: знакомство со
Scikit-Learn на классических наборах (ирисы, задание — пингвины). Она
не входит в конвейер и берёт данные из seaborn, поэтому ей нужен интернет.

### МЛГ-версия «Введения в машинное обучение»

Чужие примеры заменены не устно, а в файле, и каждый подкреплён расчётом
на учебном корпусе курса:

| было | стало | число |
|---|---|---|
| кредитоспособность заёмщика | тип контента деревом решений | точность **0,631**, правила читаются |
| стоимость ценных бумаг | сколько места займёт перевод | R² = **0,79**, расширение **+10 %** |
| сегментация рынка | разложить незнакомый корпус | ARI = **0,172** и объяснение, почему так и надо |
| полки магазина | сочетания для глоссария | биграммы по PMI против частоты |

Десять иллюстраций строятся скриптом `Лекции/tex/собрать_иллюстрации.py`
из `Л.р/data/loc_corpus.csv`; пересобрать любую презентацию —
`xelatex <имя>.tex` дважды в `Лекции/tex/`. Оформление у всех шести общее и
лежит в `mlg_preamble.tex`.

Если Calibri и Consolas нет (macOS, Linux), преамбула сама берёт шрифты из
TeX Live: Carlito, совпадающий с Calibri по ширине знаков, и DejaVu Sans
Mono. Переносы строк и раскладка слайдов те же, начертание букв немного
другое. PDF в `Лекции/` собраны именно так.

### «Текст как данные»: графики и формулы

Блоки 1-4 расширены: везде, где раньше было словесное объяснение, теперь
есть формула и разбор на числах корпуса.

- **Блок 1.** TF-IDF по формуле на одном сегменте (совпадает с sklearn до
  знака), закон Ципфа и разреженность векторов.
- **Блок 2.** Косинус вручную; весь цикл обучения на одной схеме; softmax,
  перекрёстная энтропия, градиент `(p − [y = k])·x` и шаг спуска — каждый
  на своём слайде. Обучение классификатора показано по шагам: кривые потерь
  и точности, рост отдельных весов, уверенность модели на двух отложенных
  сегментах, размер шага, границы классов на двух координатах LSA, вклад
  n-грамм в решение.
- **Блок 3.** N-граммная модель и перплексия в формулах, кривая перплексии
  по порядку модели, внимание как softmax.
- **Блок 4.** BLEU и chrF по формулам Л.р. № 3, разобранные вручную до
  0,779, 0,408 и 0,602, и обе метрики на всём корпусе.

Графики `fig/tad_*.pdf` и все числа к ним (`fig/tad_facts.json`) строит
`python собрать_иллюстрации_текст.py ../../Л.р/data fig` из `Лекции/tex/`.
Градиентный спуск в нём написан вручную, чтобы процесс было видно по
шагам; со штрафом, как в sklearn, он приходит к тем же весам, что
`LogisticRegression`, и скрипт это проверяет.

## Запуск

```
pip install -r requirements.txt
jupyter notebook
```

Ноутбуки открываются **из папки `Л.р`** — пути к данным относительные.

Работы № 1-3 выполняются на процессоре за секунды. Единственное, что
требует сети, — загрузка учебного корпуса `20 newsgroups` в разделе 13
Л.р. № 1 (около 14 МБ, потом берётся из кэша); при отсутствии сети
раздел сообщает об этом и не прерывает работу.

Л.р. № 4 требует TensorFlow и осмысленна на GPU (подойдёт Google Colab).

### Журнал

Баллы 0–10 за каждую работу. Вся группа видит весь журнал по **коду группы**,
правит только преподаватель по **паролю**.

Репозиторий и сайт публичные, поэтому ФИО и баллы хранятся только
шифротекстом: файл `journal.json` в ветке `journal` (а не в `main`).
Шифрование выполняется в браузере: AES-256-GCM, ключ получается из кода или
пароля через PBKDF2-SHA256 с 600 000 итераций. В файле два зашифрованных
блока с одними и теми же данными: один открывается кодом группы, другой
паролем преподавателя. Код — 12 знаков, около 59 бит, его генерирует
страница; перебрать его по публичному файлу нереально. Восстановить пароль
нельзя.

Кнопка «Сохранить» кладёт новый `journal.json` в ветку `journal` через
GitHub API и запускает пересборку сайта; группа видит изменения через
1–2 минуты. Для этого нужен токен:

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token.
2. Repository access: **Only select repositories** → `basic-linguistic-ml`.
3. Permissions → Repository: **Contents — Read and write**,
   **Actions — Read and write**.
4. Expiration — до конца семестра.

Токен вводится на странице журнала после входа. По умолчанию он живёт до
закрытия вкладки, с галочкой — хранится в браузере. В журнал он не
попадает. Без токена «Сохранить» скачивает `journal.json`, и его можно
загрузить в ветку `journal` вручную, а затем запустить Actions → «Сайт
курса» → Run workflow.

Что стоит знать:

- Кто знает код, видит весь журнал. Если код ушёл за пределы группы,
  смените его («Сменить код группы» → «Сохранить») и раздайте новый.
  **Старые версии файла остаются в истории ветки `journal`** и открываются
  старым кодом. Если это важно, историю ветки можно переписать: оставить
  один коммит с текущим файлом и сделать force-push.
- Fine-grained токен нельзя ограничить одной веткой: с ним можно писать во
  весь репозиторий. Не храните его на чужих устройствах.
- ФИО и оценки — персональные данные. В открытом виде они не публикуются
  нигде, но решение выкладывать журнал даже зашифрованным остаётся за
  преподавателем и правилами вуза.

### Сдача работ

Студент открывает `submit/` (или «Сдать работу» в карточке работы), вводит
код группы, выбирает себя в списке, работу и файл. Ноутбук проверяется ещё
до отправки: запущены ли ячейки, нет ли ошибок, та ли это работа. Файл
шифруется в браузере открытым ключом преподавателя и уходит на сервер приёма
`https://submit.konkin-nikita.ru` (сервис из `submit-server/`, Docker на
сервере преподавателя). Студент получает квитанцию с номером и контрольной
суммой.

Расшифровать работы может только журнал преподавателя: закрытый ключ лежит
в ящике, который открывается паролем. В журнале после входа — панель
«Сданные работы» (список, скачивание по одной и архивом, все версии) и
метки «сдано» в таблице: столбец сопоставляется с работой по полю `journal`
из `course.toml`, содержащемуся в названии столбца.

Ключ создаётся сам при первом входе в журнал; после этого журнал нужно
**один раз сохранить**, иначе страница сдачи ключа не увидит. Устройство
сервера и его развёртывание — в [submit-server/README.md](submit-server/README.md).

### Почему имена файлов берутся с диска

`Л_р_№3_Машинный_перевод_и_оценка_качества.ipynb` записан в нормализации
**NFD**, остальные ноутбуки — в **NFC**. На macOS разница не видна, на Linux
это разные имена, и путь, написанный литералом, в CI не найдётся.
`scripts/run_notebooks.py` читает имена через `os.listdir`, поэтому берёт
ровно те байты, что лежат на диске, и работает в обеих системах.

Проверить, что имена в порядке:

```
python -c "import os,unicodedata as u; [print('NFD' if n!=u.normalize('NFC',n) else 'NFC', n) for n in sorted(os.listdir('Л.р')) if n.endswith('.ipynb')]"
```

Если захочется привести всё к NFC, файл достаточно переименовать — содержимое
не меняется.

### Отрицательные результаты и средства против них

В материале три места, где метод не работает. Каждое **сопровождается
разбором средств, которые повышают качество**, и каждое средство измерено:

| где | что не работает | средство | что оно даёт |
|---|---|---|---|
| № 1, разделы 12-13 | точность упирается в 0.75 | больше размеченных данных | на реальном корпусе: 160 примеров → 0.55, 1800 → 0.83 |
| № 2, разделы 5-6 | LSA не ловит синонимию, ARI близок к нулю | готовые многоязычные эмбеддинги | нужный сегмент поднимается на 2-е место из 160; ARI вырастает в несколько раз |
| № 3, разделы 7-8 | BLEU не видит поломок и штрафует синонимию | формальные проверки + семантическая близость | проверки помечают 5 % корпуса против 49 % у порога по BLEU |

Ни одно средство не решает задачу полностью, и это тоже часть материала:
эмбеддинги не чинят кластеризацию, семантическая близость не видит
сломанный плейсхолдер. Вывод, к которому приходит студент, — **приёмка
строится из нескольких средств, а не из одного числа**.
